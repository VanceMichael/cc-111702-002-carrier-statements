# 承运月结资料的跨期抵扣领取与挂账工作台
本项目用于逐月领取承运商的原始费用清单，并把针对错收费用的调整凭据、逐笔抵扣应用及实际结算去向一并收进账单收件台。按运单汇集费用行并给出月度收件总额，同时保留费用发生期、凭据开立期、结算应用期的区别。
运行环境为 Node.js 22.23.4，仅使用标准库，没有运行时安装步骤。数据均为本地合成资料，默认来源只监听回环地址，不连接真实业务网站或真实账号。
## 运行
```bash
npm run build
npm test
npm run demo
```
演示会在进程内启动实际本地 HTTP 来源，依次办理一至三月的收件与跨期抵扣，打印领域结果及来源请求，然后关闭服务。端口由系统分配，数据保存在内存，不影响已启动的服务。
持续运行时先执行 `npm run source`，再在另一个终端执行 `npm start`。默认来源端口为 4101，业务端口为 4100；可通过 `SOURCE_URL`、`PORT` 和 `STATE_PATH` 指定回环来源、端口及状态文件。终止进程使用 Ctrl+C。删除 `var/` 可清空本地持久状态。
## 业务接口
`POST /collect` 接收本次办理参数（`{ "month": "2026-02" }`，空对象使用本地样例的正常条件）；`GET /state` 查询当前业务结果；`GET /health` 查询服务状态。一次办理失败不会提交中间业务状态，接口以 422 返回拒绝原因。状态文件按完整写入后替换，单进程内串行办理。
- `fees`：按费用行给出原始金额、已核实抵扣与待核实标记，并可沿一笔费用查到关联凭据。
- `vouchers`：调整凭据原额、状态、分次应用明细、可领取余额及效果（含申诉、撤回未使用、使用后冲回）。
- `periods`（`months`为同内容别名）：分月给出原始收件总额、运单口径、本期开立凭据、本期结算应用、抵扣去向、证据清单与`complete`完整性。
- `evidence`：跨月证据时间线；`pending`：源端暂缺分配明细的待核实缺口。
来源接口的字段约定见 `docs/source-contract.md`，业务边界见 `docs/operations.md`。`fixtures/source.json` 是可独立启动的来源响应数据，来源 `GET /trace` 返回实际请求；脚本每条路由依次返回响应，超出后重复最后一条，可表达延迟、断连和明确拒绝。请求轨迹只记录是否带授权，不回显授权原文。
## 跨期抵扣处理原则
抵扣不改写原始费用行：二月抵扣一月错收费用时，一月账单与运单金额保持原样，抵扣只经凭据（adjustment）和逐笔应用（application）登记。一张凭据可分次抵扣多张结算单，同一费用行也可挂多张凭据。源端只给部分明细时该月保持待核实（`complete:false`），不按总额配平；补件重收只补原缺口，不产生第二笔调整。工作台只做可靠收件与关联，不替财务裁定争议费用是否合理。
## 测试
测试覆盖领域正常结果、跨期抵扣链路、待核实缺口与补件、撤回与冲回区别、原件不可变与重收幂等、状态重开、HTTP 办理与查询、来源拒绝后的回滚、并行存储更新、本地访问边界和来源请求追踪。每个测试使用临时端口与独立状态，不依赖执行顺序。构建仅检查源码语法，不获取依赖。
