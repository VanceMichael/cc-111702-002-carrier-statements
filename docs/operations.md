# 业务运行边界
当前可查询：收费身份、原始账单、调整凭据、逐笔抵扣应用、账期收件总额、账期完整性、证据时间线。
当前写入操作：月份清单领取（同一次办理内沿清单引用收齐凭据与应用明细）。
同一账单内收费身份不可重复；同一费用行可对应多张调整凭据；一张凭据可分次抵扣多张结算单。

## 原始依据
来源请求保存方法、路径、状态、字节数与响应摘要，不保存授权原文。拒绝或不完整响应不能作为领域收件成功；业务结果和请求收据分别可查。进程内的写入序列只保证本进程存储互斥，不代表来源具备幂等或多进程协调能力。

## 领域决定
- 费用职责核对原始收费粒度并区分运单与费用；原始账单只收件，任何抵扣都不改写费用行金额，一月原始账单不会因二月抵扣消失。
- 凭据职责接纳调整凭据与逐笔应用，校验凭据原额、分次抵扣累计、冲回上限及撤回凭据不得留有已用额；同一笔退款只在其实际应用的月份出现一次，不重复计入两个月。
- 账期职责防同一期跨单重复费用，并按费用发生期、凭据开立期、结算应用期分别归集；月度收件总额只含原始费用，抵扣额在appliedDeductions中单独呈现。
这些拒绝属于当前正常办理契约，不代表来源失败可视为业务成功。各决定在状态提交前完成，拒绝不会消耗本地办理状态。

## 待核实与完整性
源端只提供部分明细（凭据或应用拒答、暂不可用、结构不合法）时，缺口登记在pending并在所属月份写入incompleteReasons，该月complete为false；已明确的其他月份与其他账单照常收件。工作台不会凭凭据总额配平、不会虚构剩余应用，也不对外声称缺明细的月份已完整。
传输层故障（断连、超时、非HTTP拒绝）仍按整笔办理失败处理，不提交中间状态。

## 补件与重收
补件或重收沿原有引用链补齐缺口：已收件的原件不可变（金额、归属、状态与应用关系被改写将拒绝办理），新引用并入原清单，不生成第二笔调整；缺口补齐后自动关闭，月份转为完整。

## 撤回与冲回的区别
- 撤回的未使用凭据（withdrawn）：可领取余额为零，且从未进入任何结算，旧账原始依据不受影响；
- 使用后冲回的凭据（reversed）：apply与reverse两笔应用都保留，净抵扣为零但可领取余额不恢复，旧账依据中可同时查到抵扣与冲回痕迹。
申诉中的凭据（appealed）只如实登记，是否合理由财务后续裁定，工作台不替代决定。
